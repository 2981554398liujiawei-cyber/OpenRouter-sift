## Threat model

### Assets

- OpenRouter upstream API key
- Local Access Keys (`sift_sk_...`)
- Desired model permissions
- Provider filters and provider access overrides
- Request metadata and control-plane settings
- OS credential store contents

### Trust boundaries

```text
Browser UI -> Control API /api/*
AI clients -> Inference API /v1/*
Sift -> OpenRouter
Sift -> OS credential store
Sift -> local JSON stores
```

### Security invariants

The G12 security implementation and regression suite establish that Local Access Keys cannot control `/api/*`, clients cannot widen Desired Models or Provider Filters, the OpenRouter key is not returned to browser plaintext or normal JSON stores, Local Access Keys are stored hash-only, request prompt/response/reasoning/tool data is not persisted, inference does not depend on metadata network I/O, and unavailable or stale hard filters fail closed.

## Control plane

- Host protection: audited and covered by the G12 security changes/tests; loopback host validation prevents arbitrary Host values in default loopback mode.
- Origin protection: audited for side-effecting `/api/*`; same-origin browser requests are accepted, while no-Origin CLI/curl management remains supported.
- CORS: no wildcard control-plane exposure is used.
- `SHIM_LOCAL_API_KEY`: `/ui` and static assets remain loadable; `/api/*` requires the control Bearer key. The browser key is held in React memory only and is not placed in URL, localStorage, or cookies.
- Non-loopback bind: control authentication is required by the safe configuration path; no silent unauthenticated full control plane is claimed.
- Managed-key control rejection: `sift_sk_...` is rejected for `/api/*` with the managed-key control-plane forbidden path.

## Credentials

- OpenRouter key: backend/session or OS credential-store boundary; never returned plaintext by `/config` or UI data.
- Local Access Keys: cryptographically random, hash-only on disk, timing-safe verification, and rejected for control-plane authorization.
- Control key: accepted only for `/api/*`, supplied as an in-memory browser Bearer after unlock, and not persisted by the browser.
- Credential store: secure-store failure does not fall back to plaintext JSON; session-only or explicit failure is used.
- Rotation: runtime priority is UI runtime > persisted secure credential > environment > none; replacement uses the new key for new requests and does not retroactively alter an already-started request.
- Persistence: OpenRouter secrets are excluded from normal JSON stores and logs.

## Privacy and logging

- Prompt, response, reasoning, and tool arguments are not persisted in request records.
- Error text is sanitized before it can enter request records.
- Logging audit and synthetic secret-pattern scans found no real `sk-or-...`, `sift_sk_...`, or Bearer secret in the current tree or release package.
- Debug logging does not intentionally emit authorization headers or full secret-bearing bodies.

## Filesystem and routing security

- Critical JSON writes use the existing atomic persistence path; malformed/corrupt stores do not crash startup.
- Unix permission handling and runtime-file exclusion were audited; runtime stores remain ignored and are not package contents.
- Static UI serving rejects traversal forms covered by the regression suite, including encoded parent traversal and platform path variants.
- Desired Models, Key Override, Incoming restrictions, and Hard Provider Filter regression tests preserve the narrowing-only boundary.
- Hard Filter unavailable, stale, or zero-eligible states remain fail-closed.
- Request body limits, malformed JSON handling, bounded request history, and bounded background enrichment/retry behavior are covered by tests.

## Network behavior

- Upstream URL construction is fixed to OpenRouter and model/path segments are encoded; model identifiers cannot select an arbitrary host.
- Client credentials and control keys are not forwarded upstream; managed requests replace authorization with the active OpenRouter key.
- Hop-by-hop and unrelated response headers are not blindly exposed.
- Retry behavior is bounded and does not retry ordinary 400/401/403 failures; abort handling cancels pending retry work.

## Release recommendation

**V1.0 BLOCKED.** The only current release blocker is missing live OpenRouter evidence for the exact installed RC. This is an evidence/credential availability blocker, not a claimed product security failure.

Before changing the version to `1.0.0` or creating a release tag, run the exact installed RC with a real OpenRouter credential that is not placed in command arguments or reports, then record successful catalog, `/v1/models`, one short inference, and restart/persistence evidence. Re-run the final CI for the evidence commit and keep the decision blocked unless every release gate is green.
